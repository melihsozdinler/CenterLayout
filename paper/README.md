# ProLiVis 2.0 — paper

`prolivis2.tex` is the manuscript. `figures/` holds the figures, all of which are
generated by the tool itself.

## Building

```bash
latexmk -pdf prolivis2.tex
```

The manuscript includes figures as PDF. Convert the generated SVGs first:

```bash
cd figures
for f in *.svg; do rsvg-convert -f pdf -o "${f%.svg}.pdf" "$f"; done
# or: inkscape --export-type=pdf *.svg
```

## Regenerating the figures

Every figure comes from driving the built application over a public BioGRID release,
through the same code path the interface uses. Nothing is drawn by hand.

```bash
cd ../web
PROLIVIS_FIGURE_SOURCE=~/Downloads/BIOGRID-CORONAVIRUS-5.0.260.tab3.zip npm run figures
```

Without `PROLIVIS_FIGURE_SOURCE` the bundled 975-record sample is used, so the pipeline
runs without a download — but the figures in the manuscript come from the full release.
Download it from <https://downloads.thebiogrid.org/BioGRID>.

`figures/figures.json` records the query, options and BioGRID release behind each
figure. That file is the manuscript's claim to reproducibility: with a deterministic
layout, it is sufficient to regenerate any figure exactly.

against an external reference set (CORUM or hu.MAP). The harness is implemented and
tested — `prolivis.calibrate` and `prolivis.ablate`, see `docs/TRUST.md` — but the
numbers are not in the manuscript, and the section says so rather than substituting an
internally derived reference set, which would be circular.

To fill it in:

2. Format as two gene symbols per line, with an optional `+`/`-` third column.
3. Run the calibration described in `docs/TRUST.md`, per preset.
4. Report AUROC, average precision and the leave-one-term-out ablation, with MIscore
   as a baseline.
